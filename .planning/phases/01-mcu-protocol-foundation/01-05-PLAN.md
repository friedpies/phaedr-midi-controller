**Hardware constraint — MCU-04 scope on this controller:**
MCU-04 requires transport note bangs for Rewind (note 91), FastForward (note 92), Stop (note 93), Play (note 94), and Record (note 95). This hardware controller has NO physical Rewind or FastForward buttons — the 4x4 grid's bottom row is Shift/Record/Stop/Play, and the upper 12 buttons are navigation functions (Phase 3). Rewind and FastForward are absent by hardware design, not an oversight. MCU-04 is satisfied on this hardware by implementing Stop (93), Play (94), and Record (95). Do NOT add phantom button assignments for notes 91 or 92.

**New main.cpp structure:**

```cpp
#include <Arduino.h>
#include <SoftPWM.h>
#include "pinDefines.h"
#include "inputManager.h"
#include "mcuProtocol.h"

InputManager inputManager;

// BOOT-01: Cascade startup animation — lights all 24 LEDs in sequence then turns them off.
// Runs blocking in setup() BEFORE usbMIDI handlers are registered. Safe because no MIDI
// callbacks are active yet. Confirms all LED hardware works on every power-on.
// LED order: K1–K16 (grid, row by row), then P1–P8 (track buttons).
static void playStartupAnimation()
{
    const int gridLeds[]  = { LED_K1, LED_K2, LED_K3, LED_K4, LED_K5, LED_K6, LED_K7, LED_K8,
                               LED_K9, LED_K10, LED_K11, LED_K12, LED_K13, LED_K14, LED_K15, LED_K16 };
    const int trackLeds[] = { LED_P1, LED_P2, LED_P3, LED_P4, LED_P5, LED_P6, LED_P7, LED_P8 };

    // Light each grid LED in sequence
    for (int i = 0; i < 16; i++) {
        SoftPWMSet(gridLeds[i], LED_MAX_BRIGHTNESS);
        delay(40);
    }
    // Then each track LED
    for (int i = 0; i < 8; i++) {
        SoftPWMSet(trackLeds[i], LED_MAX_BRIGHTNESS);
        delay(40);
    }
    // Hold briefly so user sees all LEDs
    delay(150);
    // Fade all off
    for (int i = 0; i < 16; i++) SoftPWMSet(gridLeds[i], 0);
    for (int i = 0; i < 8; i++)  SoftPWMSet(trackLeds[i], 0);
    delay(300);  // allow SoftPWM fade to complete
}
// Total animation duration: 24 × 40ms + 150 + 300 = ~1.4 seconds

// SysEx handler — forwards to MCUProtocol state machine
void handleSysEx(const uint8_t* data, uint16_t length, bool complete)
{
    mcuProtocol.handleSysEx(data, length, complete);
}

// NoteOn from Logic — LED state feedback
// velocity 127 = LED on, 1 = blink (Phase 2), 0 = LED off
void handleNoteOn(byte channel, byte note, byte velocity)
{
    inputManager.handleNoteMessage(note, velocity);
}

// NoteOff from Logic — LED off
// Some Logic versions send NoteOff instead of NoteOn(vel=0) for LED-off state
void handleNoteOff(byte channel, byte note, byte velocity)
{
    inputManager.handleNoteMessage(note, 0);  // treat NoteOff as velocity 0
}

void setup()
{
    SoftPWMBegin();             // initialize SoftPWM before any SoftPWMSet calls
    playStartupAnimation();     // BOOT-01: cascade animation confirms LEDs work on power-on
    inputManager.init();
    mcuProtocol.begin();

    usbMIDI.setHandleSystemExclusive(handleSysEx);
    usbMIDI.setHandleNoteOn(handleNoteOn);
    usbMIDI.setHandleNoteOff(handleNoteOff);
    // Note: CC handler intentionally removed — per CONTEXT.md clean break decision
    // Note: handleStart/handleClock/handleStop will be added in Phase 4 for beat chaser
}

void loop()
{
    inputManager.readAll();
    mcuProtocol.update();  // handles handshake retry timer
    usbMIDI.read();
}
```

- Remove `#include <MIDIUSB.h>`, `#include <MIDI.h>`, `#include <MIDI.hpp>` (these were incorrect includes for Teensyduino; `usbMIDI` is provided by Teensyduino core directly)
- Remove `#define ENABLEMIDI 1` and its `#ifdef` guard — Teensyduino USB MIDI is always present when the build flag `-DUSB_MIDI_SERIAL` is set
- Remove `handleControlChangeMessage` callback — CC routing is gone (clean break per CONTEXT.md)
- Remove `handleStart`, `handleStop`, `handleClock` stubs — Phase 4 adds these back for beat chaser
- Add `SoftPWMBegin()` in setup() — moved from inputManager.init() since SoftPWM must be initialized before SoftPWMSet calls; or keep it in inputManager.init() if that already handles it (check existing code)
- Register SysEx callback using 3-argument form (`const uint8_t*, uint16_t, bool`) — per RESEARCH.md pitfall 4

**Note on SoftPWMBegin location:** The existing `inputManager.cpp` calls `SoftPWMBegin()` at the start of `init()`. If the new InputManager::init() still calls `SoftPWMBegin()`, do NOT add it again in main.cpp setup(). Avoid double initialization. Check the new inputManager.cpp from Task 1 — if `SoftPWMBegin()` is there, remove it from main.cpp.

**Note on MIDI.h includes:** The existing main.cpp had incorrect `#include <MIDIUSB.h>` and `#include <MIDI.h>` includes. For Teensyduino, `usbMIDI` is a global object provided by the Teensy core when USB MIDI is enabled — no explicit include is needed. Removing these incorrect includes may actually fix a latent compilation issue.

Per CONTEXT.md: "No multi-protocol support, no compile-time mode switch" — no `#ifdef ENABLEMIDI` guard.
