Create `src/fader.h` and `src/fader.cpp`. The Fader class is a parallel to Potentiometer but sends Pitch Bend instead of CC, on a per-fader MIDI channel.

**src/fader.h:**
```cpp
#ifndef fader_h
#define fader_h

#include <Arduino.h>

class Fader
{
public:
    // midiChannel: 1-8 (fader 1 = channel 1, fader 8 = channel 8)
    Fader(int pin, int midiChannel);
    void read();

    // Noise threshold: proportionally equivalent to Potentiometer's ANALOG_NOISE=3
    // on 0-1023 ADC mapped to 0-16383 range. 3/1023 * 16383 ≈ 48.
    // Increase to 64 or 96 if Logic fader display shows jitter.
    static const int FADER_NOISE_THRESHOLD = 48;

private:
    int _pin;
    int _midiChannel;
    int _lastFader14bit;
};

#endif
```

**src/fader.cpp:**
```cpp
#include "fader.h"

Fader::Fader(int pin, int midiChannel)
    : _pin(pin), _midiChannel(midiChannel), _lastFader14bit(-1)
{
}

void Fader::read()
{
    int raw = analogRead(_pin);  // 0-1023 (10-bit ADC on Teensy 3.5 default)

    // Map 10-bit ADC to 14-bit MCU fader range (0-16383)
    int fader14bit = map(raw, 0, 1023, 0, 16383);

    // Suppress output if change is within noise threshold
    if (_lastFader14bit < 0 || abs(fader14bit - _lastFader14bit) > FADER_NOISE_THRESHOLD) {
        _lastFader14bit = fader14bit;

        // CRITICAL: Teensyduino sendPitchBend expects signed -8192 to +8191.
        // MCU spec uses 0-16383. Apply -8192 offset to convert.
        // Without this offset, values above 8191 are clamped and Logic fader
        // only moves in the lower half of travel.
        int pitchBendValue = fader14bit - 8192;
        usbMIDI.sendPitchBend(pitchBendValue, _midiChannel);
    }
}
```

**MCU-06 note (knob CC reassignment):**
The Potentiometer class is correct as-is for knobs — it already sends `usbMIDI.sendControlChange`. Only the CC numbers passed to the Potentiometer constructor in InputManager need changing (from CC 14–15, 28–31, 118–119 to CC 16–23). KNOB_6 → CC 21  (was CC 31)
```
KNOB_7 → CC 22  (was CC 118)
KNOB_8 → CC 23  (was CC 119)
```

Add this mapping as a block comment in `fader.h` for reference during Plan 05 InputManager wiring.

**Note on MCU-06 format:** The existing Potentiometer sends absolute CC values (0–127). True MCU VPot encoders use relative format (0x41=CW+1, 0x01=CCW+1), but since this hardware uses physical analog potentiometers (not rotary encoders), sending absolute 0–127 values on CC 16–23 is the correct approach. Logic Pro interprets these as absolute VPot position.
