## Bug 1: Handshake still not completing (BLOCKING)

**Symptom**: Buttons still trigger ripple animation when Logic is connected. `isHandshakeComplete()` returns false even though Logic IS sending note feedback (P button LEDs update correctly from Logic).

**Diagnosis**: The challenge-response bypass should have fixed this. Since it didn't, the SysEx reply from Logic is either not being received, or the header/length check is rejecting it before `validateChallengeResponse` is ever called.

**Likely root causes to investigate**:
1. `memcmp(data, MCU_HEADER, 5)` — does Teensyduino's SysEx callback include F0 in `data[0]`? If not, the header check fails silently before reaching our bypass.
2. `length < 18` check — if Teensyduino excludes F7 from length, a valid 18-byte message arrives with length=17 and is discarded.
3. Logic may never send the 0x02 Host Connection Reply at all — Logic may just start sending state without completing the handshake from its side. In that case, `_handshakeComplete` must be set by a different trigger (e.g., any incoming note/CC from Logic = connected).

**Fastest fix to try**: Add a `Serial.print` in `handleSysEx` to see if it's ever called and what `length` and `data[0]` are. Alternatively: set `_handshakeComplete = true` directly in `begin()` and skip the SysEx handshake entirely — Logic still sends state, we just start in connected mode.

## Bug 2: Track SELECT note indexing off for tracks 9+ (non-blocking)

**Symptom**: Clicking tracks 1–8 in Logic highlights P1–P8 correctly. Tracks 9+ highlight wrong P buttons.

**Diagnosis**: This is expected MCU behavior — Logic sends SELECT notes 24–31 for whichever 8 tracks are in the current bank view. When bank scrolls to tracks 9–16, Logic still sends notes 24–31 (relative to the bank), which map to P1–P8. So "wrong" highlighting at 9+ may actually be correct MCU protocol. Needs clarification: does the user want absolute track addressing or bank-relative (standard MCU)?

If bank-relative is correct: the "wrong" behavior is a user expectation mismatch, not a code bug.
If absolute is desired: not achievable with standard MCU SELECT notes — would require custom non-MCU logic.
