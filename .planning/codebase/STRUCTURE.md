## Directory Purposes

**src/ — Firmware Implementation:**
- Purpose: All firmware source code (entry point, device drivers, protocol, orchestration)
- Contains: `.h` headers and `.cpp` implementations
- Key files: `main.cpp` (entry point), `inputManager.cpp` (orchestrator), device drivers

**lib/SoftPWM/ — PWM Library:**
- Purpose: Vendored SoftPWM library for LED fading (not in package manager)
- Contains: `SoftPWM.h/cpp`, `SoftPWM_timer.h`
- Key files: `SoftPWM.h` — provides `SoftPWMSet(pin, brightness)` and `SoftPWMSetFadeTime()`
- Committed: Yes (vendored, critical dependency)

**include/ — Arduino Headers:**
- Purpose: Teensyduino and standard library includes (empty after git clone)
- Committed: No (generated during build)

**test/ — Test Suite:**
- Purpose: Unit tests for firmware (PlatformIO test framework)
- Key files: Likely empty or minimal (project is hardware-first)
- Committed: Present but see latest commits

**assets/STLs/ — Hardware Design:**
- Purpose: 3D models for enclosure/mounting
- Committed: Yes (hardware design artifacts)

**.planning/codebase/ — This Directory:**
- Purpose: Analyzed architecture/structure/conventions/testing docs
- Generated by: GSD map-codebase commands
- Committed: Yes (shared codebase knowledge)

**.planning/phases/ — Implementation Phases:**
- Purpose: GSD phase breakdowns, tasks, and summaries
- Generated by: GSD plan-phase and execute-phase commands
- Committed: Yes (shared work tracking)

**.planning/research/ — Technical Research:**
- Purpose: External API docs, protocol findings, decision logs
- Committed: Yes (shared knowledge base)

## Key File Locations

**Entry Points:**
- `src/main.cpp`: Firmware entry point — `setup()` and `loop()`

**Core Orchestrator:**
- `src/inputManager.h/cpp`: Central dispatcher for all inputs, manages NoteRegistry, ripple animation, track selection

**Hardware Abstraction (Input Devices):**
- `src/button.h/cpp`: Legacy button class (deprecating; MCUButton is preferred)
- `src/mcuButton.h/cpp`: MCU protocol button with LED control and blink FSM
- `src/potentiometer.h/cpp`: Analog input (knobs, sliders) with absolute/relative modes
- `src/fader.h/cpp`: Pitch bend fader with pickup mode and bank switch detection

**Protocol & Feedback:**
- `src/mcuProtocol.h/cpp`: MCU SysEx handshake state machine
- `src/noteRegistry.h/cpp`: Maps incoming note numbers to buttons for LED feedback
- `src/mcuConfig.h`: MCU note number constants and mode button definitions

**Configuration & Pinouts:**
- `src/pinDefines.h`: Hardware pin assignments (switches, LEDs, analog inputs)

## Naming Conventions

**Files:**
- Lowercase with camelCase: `inputManager.h`, `mcuButton.cpp`
- One class per `.h`/`.cpp` pair (with few exceptions)
- Header guards: `#ifndef class_name` (lowercase with underscores)

**Classes:**
- PascalCase: `InputManager`, `MCUButton`, `Potentiometer`, `MCUProtocol`, `NoteRegistry`
- MCU-related classes prefixed with `MCU`: `MCUButton`, `MCUProtocol`, `mcuConfig.h`

**Functions & Methods:**
- camelCase: `readAll()`, `handleNoteMessage()`, `setLedState()`, `isHandshakeComplete()`
- Private methods prefixed with underscore: `_triggerRipple()`, `_setDawValue()` (not consistently applied)
- Getters with `get`: `getButton()`, `getLedPin()`
- State queries without prefix: `isHandshakeComplete()`, `isBlinking()`

**Variables & Constants:**
- Local variables: camelCase: `fader14bit`, `originIdx`, `blinkPeriod`
- Member variables: underscore prefix: `_buttonPin`, `_ledPin`, `_noteNum`, `_pickupState`
- Static constants: UPPER_SNAKE_CASE: `DEBOUNCE_TIME`, `NUM_GRID_BUTTONS`, `MCU_HEADER`
- MIDI config constants: `MCU_NOTE_*` or `MIDI_CH_*`

**Structures & Enums:**
- PascalCase: `RippleState` (struct), `PickupState` (enum)
- Enum values: UPPER_SNAKE_CASE: `SYNCED`, `OUT_OF_SYNC`

## Where to Add New Code

**New Button (Grid or Track):**
- Define pin in `src/pinDefines.h`
- Add `MCUButton` instance to appropriate array in `src/inputManager.h`
- Call `setup()` in `InputManager::init()` (`src/inputManager.cpp:8-92`)
- If LED feedback: register note in `NoteRegistry::registerButton()` call

**New Knob or Slider:**
- Define ADC pin in `src/pinDefines.h`
- Add `Potentiometer` instance to `src/inputManager.h` (outside class) or as member array
- Initialize in `InputManager::init()`
- Call `read()` in `InputManager::readAll()` (`src/inputManager.cpp:190-212`)

**New MCU Protocol Feature:**
- Add SysEx message type constant to `src/mcuProtocol.h`
- Extend `handleSysEx()` in `src/mcuProtocol.cpp` with new message case
- Add helper method for sending new message type
- Register with `usbMIDI.setHandle*()` in `main.cpp:setup()`

**New MIDI Handler:**
- Add callback function in `src/main.cpp` (e.g., `handleControlChange()`)
- Register with `usbMIDI.setHandle*(callback)` in `setup()`
- Route to appropriate InputManager or MCUProtocol method

**New Animation or LED Effect:**
- Add state struct similar to `RippleState` in `InputManager` private section
- Add trigger method (e.g., `triggerEffect()`)
- Add update method (e.g., `updateEffect()`)
- Call from `loop()` at appropriate point

**New Utility or Helper:**
- If device-specific: add to corresponding driver class (`src/button.cpp`, `src/mcuButton.cpp`, etc.)
- If cross-device: add to `InputManager`
- Avoid creating new files unless it's a distinct device class or protocol module

## Special Directories

**lib/ — Vendored Dependencies:**
- Purpose: Libraries not available via PlatformIO package manager
- Generated: No (pre-added to repo)
- Committed: Yes (must include SoftPWM for PWM control)
- Contains: Only `SoftPWM/` currently

**.pio/ — Build Artifacts:**
- Purpose: PlatformIO build cache, dependency downloads, compiled objects
- Generated: Yes (during `pio run`)
- Committed: No (in .gitignore)
- Do NOT edit: automated by PlatformIO

**include/ — Teensyduino Headers:**
- Purpose: Copied from Teensyduino SDK during build
- Generated: Yes
- Committed: No
- Do NOT edit: regenerated on every build

**test/ — PlatformIO Test Framework:**
- Purpose: Native or on-device testing (if used)
- Pattern: One `.cpp` per test suite, mirrors `src/` structure
- Committed: Present but likely empty
- To run: `pio test`

**.planning/ — GSD-Generated Planning:**
- Purpose: Codebase analysis (this file), phase breakdowns, research notes
- Generated: By GSD commands (/gsd:map-codebase, /gsd:plan-phase, /gsd:execute-phase)
- Committed: Yes (shared work artifacts)
- Do NOT edit manually: regenerated by orchestrator on phase completion

## Build Configuration

**platformio.ini — Platform I/O Configuration:**
- Target environment: `teensy35`
- Arduino framework
- Build flags: `-DUSB_MIDI_SERIAL` (enables USB MIDI + Serial simultaneously)
- Dependencies: `Bounce2` (button debouncing), `SoftPWM` (LED PWM fading)

**Key Settings:**
```ini
[env:teensy35]
platform = teensy
board = teensy35
framework = arduino
lib_deps =
    Bounce2@^2.70
    SoftPWM@^1.0.1
build_flags = -DUSB_MIDI_SERIAL
```
